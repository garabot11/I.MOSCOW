# 🚇 I.MOSCOW

### Обнаружение посторонних объектов перед беспилотным поездом в тоннеле метро по данным 3D-лидара

Строит модель *нормального* тоннеля и сообщает обо всём, что оказалось в габарите поезда и не похоже
на тоннель. Три детектора — кластеры точек (Д1), лучевой по снимку дальностей (Д2) и нейросеть U-Net
на GPU (Д3) — и подтверждение во времени: объект сообщается, когда его видят и Д1, и Д2.

## ✨ Коротко

|  |  |
|---|---|
| **Вход** | поток `sensor_msgs/PointCloud2` с лидара на голове поезда: rosbag2 (SQLite3 / MCAP) или живой топик; топик, оси датчика и `frame_id` определяются автоматически (Hesai, Seyond Falcon Prime) |
| **Выход** | `/obstacles/status`: `CLEAR` / `DETECTED` / `UNKNOWN`, расстояние до ближайшего препятствия, до какой дальности путь проверен, режим GPU/CPU, данные по каждому объекту; маркеры для RViz |
| **Метод** | модель рельса и оси пути → габаритная коробка → три детектора (воксельные кластеры, лучевой по снимку дальностей, U-Net) → отбраковка конструкций тоннеля → слияние по трекам и подтверждение во времени |
| **Качество** | 0 ложных кадров на всех 6 записях организаторов и на 20-минутной поездке (13 759 кадров); объект на 56 м — с кадра 11; тёмный человек на Falcon Prime — с 154 м, стоя на 100 м виден в 510 из 510 кадров; вставленные организаторами объекты: стена — с 76 м, плита — с 91 м, кубы 0,3 м — с 37–52 м; синтетика организаторов с разметкой — найдены все 7 объектов в габарите и 8 из 13 по всему списку, 0 ложных |
| **Скорость** | 8 закреплённых ядер ноутбука, GPU: p95 39–75 мс на кадр, ни одного кадра дольше 100 мс из 3480; Д3 на GPU — 8–21 мс в отдельном потоке |
| **Ресурсы** | GPU (NVIDIA, PyTorch cu128) для Д3 с автоматическим аварийным режимом CPU; Д1/Д2 — NumPy + SciPy; один узел ROS 2 |

## 🧠 Как это работает

```mermaid
flowchart LR
    A["☁️ PointCloud2"] --> B["Проверка облака,<br/>оси датчика"]
    B --> C["Уровень рельса<br/>и ось пути"]
    C --> D["Габаритная<br/>коробка"]
    D --> E1["Д1: воксельные<br/>кластеры"]
    D --> E2["Д2: лучевой по<br/>снимку дальностей"]
    D --> E3["Д3: U-Net<br/>на GPU"]
    E1 --> F["Отбраковка<br/>конструкций"]
    E2 --> F
    F --> G["Слияние по трекам:<br/>Д1 и Д2 согласны"]
    E3 --> G
    G --> H["📡 /obstacles/status<br/>CLEAR · DETECTED · UNKNOWN"]
```

1. **Уровень рельса** — робастная подгонка по полотну, дальше полотна — по профилю потолка.
2. **Ось пути** — четыре источника: симметрия полотна, центр лотка, середина свободного пространства между
   стенами и потолком, цепочка сдвигов профиля. Коридор следует за поворотами.
3. **Габарит** — полуширина 1,0 м внизу и 1,4 м по кузову, от 0,3 до 3,4 м над рельсом; запасы растут с
   дальностью и кривизной. Коридор строится только до дальности, где тоннель опознан (`verified_to_m`).
4. **Три детектора**: Д1 — воксельные кластеры с правилами, которые отсеивают стены, колонны, края платформ и
   оборудование; Д2 — препятствие как «тень» в снимке дальностей; Д3 — нейросеть U-Net (препятствие / пыль).
5. **Слияние**: объект подтверждается, когда Д1 и Д2 видят его в одном месте; Д3 добавляет вес. Треки
   удерживают объект во времени. Расстояние — от лидара до ближайшей поверхности объекта.

## 🚀 Быстрый старт

Нужны Docker, драйвер NVIDIA ≥ 570 и NVIDIA Container Toolkit; без GPU решение работает в аварийном режиме
CPU с предупреждением. **Пошаговое руководство с проверкой GPU и разбором ошибок —
[solution/docs/launch.md](solution/docs/launch.md).**

**1. Получить образ** (один раз): архив 4,5 ГБ лежит в [релизе v3](https://github.com/garabot11/I.MOSCOW/releases/tag/v3)
частями по 95 МБ.

```bash
mkdir -p dist && cd dist
base=https://github.com/garabot11/I.MOSCOW/releases/download/v3
for f in metro-lidar-final.parts.sha256 metro-lidar-final.tar.gz.sha256 metro-lidar-final.image.txt \
         $(seq -f 'metro-lidar-final.tar.gz.part-%02g' 0 44); do curl -fL -C - -O "$base/$f"; done
sha256sum -c metro-lidar-final.parts.sha256                      # проверка частей
cat metro-lidar-final.tar.gz.part-* | gunzip | docker load       # → metro-lidar:gpu-dev, ID a0e1e7e33476
```

…или собрать: `cd solution && docker build -t metro-lidar:gpu-dev .` (нужен интернет, ≈ 4,5 ГБ загрузки).

**2. Запустить одной командой** — самопроверка, детектор, RViz и консоль статуса:

```bash
cd solution
./run.sh --data /путь/к/датасету          # каталог с папками rosbag2 (любая вложенность)
```

**3. Во втором терминале — проиграть запись:**

```bash
./run.sh bags                             # список записей
./run.sh play doubleT_obstacle            # ПРОБЕЛ — пауза, ↑/↓ — скорость; другая запись — без перезапуска
./run.sh stop                             # остановить контейнер
```

## 📡 Выход

`metro_obstacle_msgs/ObstacleStatus` публикуется на каждое облако:

| поле | смысл |
|---|---|
| `status` | `0 UNKNOWN` · `1 CLEAR` · `2 DETECTED` |
| `distance_m` | расстояние от лидара до ближайшего подтверждённого препятствия, м |
| `verified_to_m` | до какой дальности в этом кадре построен и проверен коридор габарита |
| `obstacles[]` | все кандидаты кадра: смещение от оси пути, высота над рельсом, размеры, число точек, уверенность |
| `mode`, `mode_reason` | `gpu` / `cpu_emergency` / `cpu_forced` и причина, если не GPU |
| `processing_ms` | время обработки облака |
| `diagnostics` | причина `UNKNOWN`: нет облаков, несколько топиков, поток прервался |

Дополнительно: `/obstacles/markers` (RViz) и `/obstacles/candidates` (точки принятых кандидатов).

## ⚠️ Ограничения

- Габарит (полуширина вагона, короба контактного рельса, края платформ) выведен из данных, а не задан
  организаторами. Объекты в 1,0–1,35 м от оси ниже 0,8 м не сообщаются (там короб контактного рельса): так
  6 из 13 объектов синтетики организаторов остались вне нашего габарита.
- Дальность ограничена тем, что видно в тоннеле: за поворотом коридор закрывается, низкие объекты видны там,
  где виден настил пути (≈ 60–120 м); малые объекты (кубы 0,3 м) — ближе ≈ 50 м.
- `CLEAR` означает «до проверенной дальности (`verified_to_m`, в прямом тоннеле ≈ 170 м) нет подтверждённого
  объекта», а не доказанную свободу пути до 300 м.
- Фильтр пыли не удерживает плотное облако пыли прямо на оси пути (проверено только на синтетике: реальной
  записи с пылью нет).
- Расстояние отсчитывается от лидара: смещение до лобовой части поезда неизвестно. Стенд организаторов
  (i7-9700E) не измерялся: на его ядрах ожидается в 1,3–1,5 раза больше времени на кадр.
